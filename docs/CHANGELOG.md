## v0.4.5 (2026-08-22)

> 摘要视角修复：对话摘要统一以主人第一人称生成，杜绝把主人当成第三方的混乱视角

### 核心亮点
- **第一人称视角加固**：`summarize_conversation` 新增显式 `owner_name` 参数，prompt 强制要求「凡是主人（我）的消息统一用『我』指代，严禁出现『我向自己…』这类把主人当成第三方的矛盾描述」。无论对方称呼主人为具体昵称还是本名，摘要一律归一到第一人称，视角不再漂移。
- **调用方兜底**：未显式传入 `owner_name` 时自动回退到 `agent.user_name`；若两者皆空则告警提示，避免手动/脚本调用时静默生成错误视角。
- **影响范围**：周期性摘要（滚动调度器）、补跑机制、主动触达推送、Web 摘要页四类生成链路共用同一 `summarize_conversation`，本次修复对全部链路生效。

### 升级注意
- 纯逻辑修复，无新增配置项；改动生效需重启 Linkora 服务。

## v0.4.4 (2026-08-22)

> 周期性摘要连续性补跑：中途停机也不丢当天的「当日 / 近七天」摘要

### 核心亮点
- **摘要连续性补跑**：新增启动期检测——系统记录「上次运行时间」，再次启动时自动计算停机时长，把遗漏的自然日窗口按天切分，**现场调 LLM 补生成**停机期间的「当日」对话摘要，并自动补全「近七天」视图。无需用户手动触发，补出的摘要与正常周期**同源同格式**（均写回 `conversation_summaries`，复用既有主动推送 / Web 摘要页的拼装链路）。
- **归日精确**：每条补跑摘要的归属时刻标记为「当日 23:59:59」，使其正确归到那一天；「近七天」视图（回溯 7 天）自然覆盖停机期，主人与 Web 端拿到的信息连续、不空洞。
- **时区稳健**：消息时间戳在库内可能混合「本地 naive」与「带 Z 的 UTC」，补跑在 SQL 粗筛后用 Python 统一归本地时区再分自然日，避免跨时区误判漏补。
- **安全兜底**：补跑在独立后台线程执行，DB / LLM 异常仅记日志、绝不拖垮主回复链路；补跑完成后刷新「上次运行时间」防下次误判；`max_backfill_days`（默认 14）上限防止极端停机刷爆 LLM 额度；单会话当日消息不足 `min_messages_per_chat`（默认 3）条则跳过，避免噪声。

### 升级注意
- 新增 `summary_backfill` 配置段，默认开启（`enabled: true`），可关或调整 `max_backfill_days` / `min_messages_per_chat`。
- 改动生效需重启 Linkora 服务（补跑调度器随启动加载）。
- Web 摘要页的「今日 / 昨日 / 近七天」三个窗口在补跑完成后会自动补齐停机期内容，无需额外操作。

## v0.4.3 (2026-08-21)

> 对话摘要页视觉重构 + 稳定性修复

### 核心亮点
- **对话摘要页全面重构**：顶部「时间窗口」分段控件（今日/昨日/近七天）与「今日汇总」入口合并为同一行工具栏；摘要内容从纯文本改为**结构化卡片**展示——头像、会话名、平台标签、消息数、自动提取的主题/关键词标签、建议待办标签，视觉层级清晰、信息密度更高。
- **默认今日视图**：打开对话摘要页默认展示「今日」窗口，最新摘要时间完整换行显示（不再截断）。
- **稳定性修复**：`get_store_dep` 不再关闭全局单例 store，修复摘要轮询偶发导致 metrics 页 500（SQLiteStore is closed）；刷新页面不再跳回首页（补全页面白名单）。

### 升级注意
- 纯前端视觉与稳定性变更，无后端配置变更；前端资源已重编 `dist/` 随版本发布。

## v0.4.2 (2026-08-20)

> Web 对话摘要实时页 + CodeQL 安全告警清零

### 核心亮点

## v0.4.1 (2026-08-20)

> 公共记忆自动注入 + 安全加固

### 核心亮点
- **公共记忆自动注入**：公共记忆（`scope=public`）每轮对话自动召回并注入 system prompt，与 RAG 知识库注入对称；个人记忆仍保持 LLM 主动调用，确保隐私边界。权重提升策略仿 RAG v5，将公共记忆块抽出为独立消息紧贴 user 之前，附「最高优先级」「覆盖声明」指令前缀，避免模型被 KB 文档误导。
- **密码日志安全加固**：移除 auth_middleware.py 中日志记录的明文密码参数，消除 CodeQL 安全告警。

### 升级注意
- 公共记忆自动注入为透明增强，无需额外配置；默认阈值 0.55 / top_k=3。如需调整，可在 `config.yaml` 添加 `memory.recall.threshold` 与 `memory.recall.top_k`。
- `docs/memory.md` 已同步更新公共记忆注入说明。

## v0.4.0 (2026-08-18)

> 距 v0.3.0（2026-08-11）以来的累计发布：认证与出站安全加固、主动触达新能力、知识库检索增强、配置安全护栏、平台能力诚实标注。

### 核心亮点
- **认证安全加固**：Web 认证中间件迁移至 `pyjwt` 标准实现（HS256），签名与过期 / 篡改校验交由成熟库处理；旧令牌格式兼容、可继续校验，移除手搓 HMAC 与 `json.loads`。
- **出站 SSRF 收口**：出站请求默认拒绝一切非全球单播地址，封死私网 / 回环 / 云元数据（169.254.169.254）/ 链路本地 / CGNAT 探测，仅放行公网与代理 fake-IP 段（198.18.0.0/15），新增边界回归测试。
- **主动触达（新能力）**：新增每日定时把近期对话摘要主动推送给主人的能力（钉钉 1:1），复用既有对话缓存摘要、不额外消耗 LLM；默认关闭，配置 `proactive.enabled=true` 并填写主人账号后启用。
- **知识库检索增强**：KB 文档列表支持关键词搜索，RAG 管理页新增搜索框（防抖、输入即重置到第 1 页），并补 `encodeURIComponent` 编码加固。
- **配置安全护栏**：CI 接入配置漂移防护，本地覆盖 `config.yaml` 前自检会丢哪些 live 独有非密钥项，从源头杜绝「整份覆盖丢参数」（即 2026-08-17 事故本质）。
- **平台能力诚实标注**：飞书 / 企业微信在真实 CLI 下不支持的日历 / 待办 / 文档 / 已读闸门等能力，已在平台能力矩阵文档中如实标注为不可用，消除「虚标可用、调用静默返回空」的黑洞；企微此前被错误暴露的日历 / 待办工具已收敛为钉钉专属。

### 升级注意
- 主动触达为可选功能：默认 `proactive.enabled=false`，对线上零行为影响；如需启用，在 `config.yaml` 配置 `proactive.owner_user_id` 或 `proactive.open_dingtalk_id` 及触发时刻。
- 安全加固无需改动配置：`config.web.jwt_secret` 仍按既有惰性解析语义工作。
- 飞书 / 企微用户此前若尝试过日历 / 待办工具（实际静默失败），升级后将收到明确的不支持提示而非空结果。

## v0.3.0 (2026-08-11)

> 距 v0.2.0（2026-08-07）以来的累计发布：JWT 认证与 RBAC、钉钉群消息/系统推送补全、会话上下文质量重构、还原度提升、前端性能优化、安全加固与文档站重设计。

### 核心亮点
- **安全加固**：JWT 认证 + RBAC（admin/operator/viewer）取代原有弱校验；签名密钥不再硬编码（`config.web.jwt_secret` 惰性解析 + 进程随机兜底，重启后旧令牌失效）；异常信息不再外泄；新增 IP 白名单防 SSRF。
- **会话上下文质量重构**：历史消息顺序归一化，修复「对话已闭环仍追问」「旧话题串味」「老消息误触发回复」；发言人姓名全链路暴露、不同人绝不跨人合并；话题边界加时间标注与断层提示。
- **钉钉群消息 / 系统推送补全**：群聊与「工作通知」此前长期拉取不到，现已通过逐群接口 + 群枚举缓存修复（实测可达 117 个群）。
- **还原度（fidelity）提升**：低置信风格回退由「中性客服」改为「有个性的人」；RAG 空结果注入风格保持指令；清洗管线误伤阈值放宽；上下文/长度上限放宽。
- **存储自愈**：存量分库列迁移自愈，修复 `no such column` 导致的 500；撤回消息改为软标记（Web 端显示「已撤回」）。
- **前端性能优化**：Chart.js 按需懒加载、FontAwesome 双字重子集、图片缩略图 WebP、仪表盘三路轮询合并为单通道、记忆列表分页。
- **文档站重设计**：品牌渐变落地页 + 设计系统（深色优先）。

### 升级注意
- 新增可选配置项 `config.web.jwt_secret`：不配置时每次启动生成进程随机密钥（重启后旧令牌全部失效），建议固定为高熵值（`secrets.token_urlsafe(48)`）。
- 上下文/长度参数默认值放宽（`history_tiering_recent` 4→8、`history_window` 6→12、`history_days` 3→7 等），无破坏性变更。

## 2026-08 上旬 · 重要变更摘要

- **安全**：JWT 硬编码密钥漏洞修复；payload 解析由 `eval` 改为 `json.loads`；异常信息脱敏；敏感数据脱敏工具；IP 白名单防 SSRF；视频/语音消息误判为图片的缺陷修复（避免整段视频被下载 OCR 并造成 ~30s 回复延迟）。
- **回复质量**：修复「对话已结束 AI 仍追问」（改为暴露发言人姓名、交由 LLM 自判，不堆正则门控）；新增话题边界软提示；新增消息年龄门槛（远古消息不触发回复）；撤回消息软标记。
- **稳定性**：存量分库列迁移自愈；list-all 路径漏存本人消息修复；防抖去重收紧（内容相同**且**时间差 ≤2s 才算重复投递）；钉钉群消息补全（117 群实测可达）。
- **前端**：移除冗余 Bootstrap JS；a11y 焦点 / ARIA 修补；工具调用排行卡片重设计；图片缩略图 WebP；Chart.js 懒加载；三路轮询合一。
- **文档站**：落地页商业级重设计；迁移至自定义 Actions 部署工作流；Python 运行版本统一为 3.14+。

## 更早的重要里程碑

- **多平台物理隔离**：钉钉 / 飞书 / 企业微信各自独立适配器、独立 SQLite 库、独立轮询器，数据互不可见。
- **双进程分离**：Web 与后台轮询器（worker）进程分离，改 Web 代码只重启 web 进程、不打断消息摄入。
- **RAG 混合检索**：BGE 本地离线向量 + BM25 重排序（0.6 + 0.4），置信度门控，低置信度转草稿 / 转人工。
- **审批转交（钉钉）**：8 个审批工具 + 通用审批子系统。
- **智能增强**：长期记忆（按用户隔离、自动压缩归档）、图片 OCR、长对话异步摘要压缩、风格人格抽取。

> 架构与设计详情见 [架构文档](architecture.md) 与 [设计总览](design.md)。
