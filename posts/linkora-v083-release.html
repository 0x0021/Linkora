Linkora v0.8.3：分身不再跟自己说话了

AI Agent v0.8.3 钉钉 修复

一个以「身份识别」为主的小版本。起因是我自己的 1:1 窗口里连着冒出两条 AI 回复，中间没有任何对方消息；查下来不是模型问题，是本人消息被当成对方、回复又被投递回本人窗口。

本文要点

  • 统一自身身份判定：ID + 正式姓名 + 昵称 + 原始字段一起比，零配置自动反推 openDingTalkId 与昵称
  • 单聊回复按入站会话 ID 直通发送，加两道拒发护栏；存量 657 条污染缓存已备份清洗
  • 启动期身份解析从约 60 秒（且常失败）降到 1.8 秒
  • 新增：主人用 Done / ✅ 表情标过的请求，摘要标为（已办）
  • 新增 mark_read_delay_seconds（默认 120）：修复连续追问第二句被已读门控永久吞掉

问题链路

钉钉消息里的 sender 是昵称，通讯录 userName 是正式姓名，senderId 是 openDingTalkId，三者字面都不同。旧逻辑只比 userId、姓名兜底又要求 sender_id 为空，于是本人单聊消息全部被判成「对方发的」。

连带三层：启动时自身 openDingTalkId 解析失败（旧实现把两个 ID 字段 or 合并后拿 oid 比 userId，恒不成立）→ 漏判的 sender_id 写进会话缓存 peer_open_dingtalk_id，657 条会话的对端全指向本人 → 单聊按「人」发 1:1，回复落进本人窗口。对方收不到，回复回灌后还成了 user 消息，污染上下文与长期记忆。

修复

一个口径。新增 src/self_identity.py，poller、运行时、发送护栏共用同一套判定，并防同名误杀。自身 openDingTalkId 与昵称在启动期从本地「我」会话缓存反推，不依赖配置、不硬编码姓名；另留一条「本人 ID 必横跨几乎所有 1:1 会话」的统计法兜底。

一条通道。chat_message_send 支持 conversation_id（--conversation-id 稳定 ID 直通），单聊优先按入站会话 ID 发，失败才降级按人发——物理上不可能串会话。飞书 / 企微适配器按能力位保持原路径。

三道护栏。入站来自本人拒发；缓存 peer 命中本人 ID 拒发；peer 与 sender 不一致时以 sender 为准（顺手修掉旧纠错只认 ou_ 前缀、对钉钉 DDn1… 从未生效的老 bug）。

存量 657 条污染记录备份后清洗，未删任何消息；服务重启后复查 15 个会话库，污染数为 0。

另外三处

表情回应 → 已办信号。钉钉表情回应是消息元数据、不进轮询流，纯文本摘要看不到「这件事已办」。现在摘要链路只读拉取本批消息的 reaction，把主人本人用完成类表情标记的请求标为（已办）；第三人回的不算，赞 / 感谢不算，读取失败静默降级。

延迟标记已读。回复成功发出后延迟 120 秒再标已读，给追问留出未读窗口；同会话二次回复重新计时，发送失败或被门控拦下不标记。设 0 恢复旧行为。

两处回归修复。出站防护残留参数导致所有联网工具抛 PoolKey TypeError 整批崩溃（并补齐此前空转的 DNS 重绑定保护）；管理台「模拟测试」历史回填因先转义后拼 JSON 变成 undefined，改为先序列化再统一转义。

升级注意

无数据迁移、无破坏性配置变更，config.yaml 零改动，工具数仍 49，不需要补工具白名单。拉代码重启即可。若此前用 requirements.txt 安装依赖，建议按 requirements.lock 重装一次以对齐 urllib3 钉版。

可选调整：poller.mark_read_delay_seconds（默认 120，0 = 立即标记）。

验证

ruff 全路径通过；pyright 零错误；依赖一致性、宽异常基线 638 / 静默 22、SSRF 出站门禁、gitleaks、前端构建与清单门禁全绿。受影响回归 837 例全过，6 处变异测试全部让新测试变红并按字节还原。CI 四个 job、CodeQL、Pages 全部 success，开放告警 0。
